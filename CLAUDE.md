# DAS-Forge core: правила для ИИ-агента

Ядро `@das-forge/core` (Node >= 26, ESM, Express 5, Zod v4, `node:sqlite`, Vitest 5). Код ядра: `packages/core`, пример приложения: `examples/workshop`. Подробные правила: `docs/engineering-rules.md`. Причины решений: `docs/adr/`. Известные упущения: `docs/gaps-core.md`, внешний аудит: `docs/audit-core-external.md`.

## Как работать
- Отвечать пользователю по-русски. Он не программист, работает на Windows, продвигает работу словом «go».
- Сначала посмотреть код, вызывающих и тесты. Перед своим кодом проверить `docs/dependencies-target.md`; если свой код лучше готовой зависимости, объяснить и спросить, а не выбирать молча.
- Минимальный диф, существующий стиль. Не глушить ошибки, не ослаблять тесты. Исправление бага = регрессионный тест.
- Работать последовательно, без параллельных субагентов (бесплатный тариф, лимиты сессий).
- Новую зависимость или обновление: сначала проверить версию на npmjs.com и прочитать changelog, сообщить о влиянии; обновлять только по правилу «первая/вторая цифра».
- Версия 0.1.x остаётся, пока пользователь явно не скажет иначе. К 0.2.0 не готовиться без его слова.

## Проверка и отчёты
- Тесты запускает пользователь на своей машине; в песочнице нет `zod` и `express`, часть тестов там не идёт.
- В каждом отчёте метки: VERIFIED, PARTIALLY VERIFIED, NOT VERIFIED, FAILED, BLOCKED. Не писать «тесты прошли», если их не запускали.
- Поведение в браузере в песочнице не проверить: так и писать.

## Выпуск версии
1. `node scripts/version.mjs set X`; запись `## [X]` сверху `packages/core/CHANGELOG.md`.
2. `npm run docs` из корня `das-forge-core/`.
3. Архив: `cd work/repo2 && zip -qr das-forge-core-X.zip das-forge-core -x '*/node_modules/*' '*/.git/*'`, предыдущий архив удалить; отдать файлом.
4. Пользователь каждый раз открывает архив в чистой папке; порядок проверки: `docs/guide/13-new-version.md`.

## Правила кода
- Деньги: целые минорные единицы. Время: UTC в хранилище.
- Чтение, решение и запись, зависящие друг от друга: `atomic(db, fn)` (`database/atomic.js`), атомарный SQL или проверка версии/отпечатка формы (`admin/edit-version.js`).
- Внешние вызовы с таймаутом; повторы только временных ошибок, с паузой `backoffDelay` (`util/backoff.js`).
- Запросы к БД только константами и `?`. В страницах нет `innerHTML`/`insertAdjacentHTML` (тест инвариантов безопасности).
- Статический контроль: `npm run lint` (ошибки роняют сборку).
- Крупное решение записывается как ADR в `docs/adr/`.
- Подтверждение пользователя нужно до: смены схемы общей БД, изменений авторизации/безопасности/CI, удаления данных, установки зависимостей.
