# Участие в разработке DAS-Forge

Спасибо, что заглянули. Проект ведёт один человек, поэтому правила простые, а сроки ответа — ориентир, не обязательство.

## Что полезно

- Сообщение об ошибке с шагами, по которым она воспроизводится ([шаблон](.github/ISSUE_TEMPLATE/bug_report.yml)).
- Предложение с описанием задачи, а не только решения ([шаблон](.github/ISSUE_TEMPLATE/feature_request.yml)). Крупные изменения сначала обсудите в issue: так не пропадёт ваш труд.
- Исправления текстов документации и переводов.
- Уязвимости — **не** в публичные issue, а по [SECURITY.md](SECURITY.md).

## Как собрать и проверить

Нужен Node.js ≥ 26 (см. `.nvmrc`).

```bash
npm install
npm install-scripts approve argon2 cpu-features ssh2   # нативные пакеты
npm test                                               # ядро и пример
npm run test:template                                  # шаблон приложения
npm run docs                                           # пересобрать docs/index.html
```

Перед pull request выполните `npm test`, `npm run version:check` и `npm run lock:check`.

## Правила изменений

1. **Один pull request — одна тема.** Ошибка и несвязанная чистка кода — отдельные.
2. **Тест вместе с кодом.** Новое поведение и исправление ошибки получают тест; тест, который проходил бы и без исправления, не считается.
3. **Тексты на двух языках.** Всё, что видит пользователь, пишется на русском и английском сразу (`packages/core/src/**/texts.js` и словари разделов); тест каталога переводов проверяет, что ключи совпадают.
4. **Документация описывает текущую версию.** Без «добавлено в X»: история только в [CHANGELOG](packages/core/CHANGELOG.md). Новая опция или команда — строка в соответствующем [руководстве](docs/guide/).
5. **Ядро даёт значения по умолчанию, приложение переопределяет.** Не зашивайте в ядро знание о конкретном приложении.
6. **Зависимости.** Сначала посмотрите [список целевых зависимостей](docs/dependencies-target.md): новый пакет без причины не добавляется. Версию проверяйте на npmjs.com, а не по памяти.
7. **Безопасность.** Не ослабляйте проверки ради удобства; тест `security-invariants` перечисляет опасные конструкции и ловит новые.
8. **Версия и журнал.** Каждая поставка повышает патч-номер (`npm run version:set -- X.Y.Z`) и добавляет запись в CHANGELOG с подразделом «Не проверено»: что не удалось проверить у вас. Это делает мейнтейнер при слиянии, если вы не договорились иначе.

## Стиль

Настройки редактора — `.editorconfig`. Код — ESM, с точками с запятой; следуйте соседним файлам. Комментарии объясняют «почему», а не «что».

## Вклад и лицензия

Отправляя pull request, вы соглашаетесь, что ваш вклад распространяется на условиях [MIT](LICENSE), как и весь проект. Подписывать отдельное соглашение не нужно.

## Поведение

Участие регулируется [кодексом поведения](CODE_OF_CONDUCT.md).
