# my-app

Шаблон приложения на ядре DAS-Forge: копируйте папку, переименуйте, заменяйте пример своей предметной областью. Описание в документации: `docs/guide/09-workshop.md`, раздел «Шаблон приложения».

## Как начать

```bash
cp -r templates/app ../my-new-app && cd ../my-new-app     # или скопируйте папку как угодно
# 1. имя: замените `my-app` в package.json, app.config.js, `My App` в src/*.js, APP на лого в assets/brand/
# 2. порт: server.port в app.config.js — следующий свободный 9N02 (схема портов — «Конфигурация»)
# 3. ядро: "@das-forge/core" в package.json — диапазон выпущенной версии (^0.2.0).
#    Пока ядра нет в npm, подставьте путь: "file:../das-forge-core/packages/core"
npm install
npm run cli -- config check
npm start             # https://127.0.0.1:9902; пароль первого администратора — в баннере и в data/first-run-admin.txt
npm test
```

В production секрет сессии берётся из окружения (`DAS_SESSION_SECRET` или `DAS_SESSION_SECRET_FILE`), а не из `app.config.js`; запуск откажется стартовать с заглушкой.

## Что где

| Файл | Что делает | Что с ним делать |
|---|---|---|
| `app.config.js` | настройки приложения; всё остальное по умолчанию | имя, порт, база, копии |
| `src/context.js` | единая сборка: конфигурация → база → брендинг → вход → копии → модули → персональные данные → почта; используют и сервер, и CLI | добавляйте свои сервисы сюда |
| `src/server.js` | Express: порядок обработчиков (описан в комментарии), админ-панель, планировщик, остановка | обычно не трогать; добавлять задачи и потоки событий |
| `src/routes.js` | вход (блокировки, ровное время ответа), выход, `/me`, смена пароля, страницы, пример API `/notes` | **заменить пример своими маршрутами** |
| `src/roles.js` | роли и права | свои роли и права |
| `src/notes.js`, `migrations/001_init.js` | пример модели: SQL без ORM, синхронная миграция | заменить своей моделью |
| `src/pages.js`, `src/messages.js` | страницы приложения без клиентского фреймворка (вход, смену и сброс пароля рисует ядро: `accounts`); тексты на двух языках (i18next) | свои страницы и тексты |
| `src/doctor-categories.js` | проверки для `doctor` и раздела «О системе» | свои категории |
| `src/banner.js` | баннер при старте | — |
| `bin/app.js` | CLI: готовые группы команд ядра | свои команды |
| `assets/brand/` | неизменяемый логотип поставщика | свой логотип |
| `test/` | тест по HTTP (настоящий стек) и тест текстов | копируйте образец для новых маршрутов |
| `Dockerfile`, `docker-compose.yml` | образ и запуск за TLS-прокси | подставьте порт и имя |

## Как удалить пример «заметки»

Удалите `src/notes.js`, маршруты `/notes` и `/ui/notes` в `src/routes.js`, функцию `renderNotesBody` и тексты `notes.*`, карточку в `renderHomeBody`, пункт меню в `routes.js`, права `*:notes` в `src/roles.js`, миграцию `001_init.js` (если база ещё не использовалась) и тесты заметок в `test/app.test.js`. Поставьте на их место свои.

## Что не входит в шаблон (берите из `examples/workshop`)

Двухфакторная аутентификация (TOTP, коды восстановления), «Забыли пароль» по почте, страница «Аккаунт», загрузка файлов, потоки событий (SSE), свой CRUD пользователей: вместо него работает раздел «Пользователи» админ-панели ядра. Каждое подключается отдельным блоком кода; образец и тесты есть в workshop.

## Обновление ядра

```bash
npm update @das-forge/core
npm test && npm run cli -- doctor
```

Перед обновлением читайте `CHANGELOG.md` ядра: пока основная версия 0, второе число означает возможные ломающие изменения.
