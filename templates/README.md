# Шаблоны: приложение и документы

В репозитории два вида заготовок: **шаблон приложения** на ядре (код) и **шаблоны документов** для организации, которая запускает приложение.

## 1. Шаблон приложения (`templates/app/`)

Минимальное, но настоящее приложение: вход, смена временного пароля, права, пример данных с API и страницей, админ-панель, CLI, миграции, резервные копии, алерты, страница «О платформе» и политики (в том числе заявление о доступности), переводы ru/en, тесты. Копируйте папку, переименуйте, заменяйте пример своей предметной областью.

```bash
cp -r templates/app ../my-new-app && cd ../my-new-app
# 1. имя: замените `my-app` в package.json, app.config.js, `My App` в src/*.js, логотип в assets/brand/
# 2. порт: server.port в app.config.js — следующий свободный 9N02
# 3. ядро: "@das-forge/core" в package.json — диапазон выпущенной версии; пока ядра нет в npm — путь "file:../das-forge-core/packages/core"
npm install
npm run cli -- config check
npm start      # пароль первого администратора — в баннере и в data/first-run-admin.txt
npm test
```

В production секрет сессии берётся из окружения (`DAS_SESSION_SECRET` или `DAS_SESSION_SECRET_FILE`), а не из `app.config.js`. Установочные скрипты argon2 и других пакетов npm может заблокировать: см. `docs/guide/01-quick-start.md`.

| Файл | Что делает |
|---|---|
| `app.config.js` | настройки приложения: имя, порт, база, копии |
| `src/context.js` | единая сборка: конфигурация → база → брендинг → вход → копии → модули → персональные данные → почта |
| `src/server.js` | порядок обработчиков, админ-панель, планировщик, остановка |
| `src/routes.js` | вход, выход, `/me`, смена пароля, страницы, пример API `/notes` — заменить своим |
| `src/roles.js` | роли и права |
| `src/notes.js`, `migrations/001_init.js` | пример модели — заменить своей |

Полное описание, удаление примера «заметки», что в шаблон не входит и обновление ядра — в [README шаблона](app/README.md). Порядок работы — `docs/guide/09-workshop.md`.

## 2. Шаблоны документов (`docs/templates/`)

Заготовки для организации-владельца приложения: ядро выполняет технические требования, а регламенты и публичные тексты пишет владелец.

| Файл | Для чего |
|---|---|
| `incident-response.md` | регламент реагирования на инцидент безопасности: роли, шаги, сроки уведомлений |
| `vulnerability-disclosure.md` | политика приёма сообщений об уязвимостях вашего приложения (как `SECURITY.md` ядра) |
| `support-policy.md` | срок поддержки версий, бесплатные обновления безопасности, сроки исправления (CRA) |
| `accessibility-statement.md` | заявление о доступности интерфейса (EAA, ГОСТ Р 52872, Section 508) |

Как пользоваться: скопируйте файл в документацию своего приложения, заполните места в `[…]`, удалите пояснения. Это заготовки, не юридические документы: сроки и ссылки на нормы сверьте с юристом.
