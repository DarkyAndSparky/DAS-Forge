# Проверка новой версии

Как принять архив с новой версией ядра и убедиться, что она работает. Каждый архив открывается в **чистой папке**, старая не заменяется: так можно вернуться к предыдущей версии и не тащить за собой чужие файлы. Команды для Windows (CMD); на Linux и macOS те же, меняются только пути.

## 1. Распаковать и перейти в папку

Распакуйте архив в новую пустую папку, например `C:\Users\<имя>\Downloads\das-forge-core-0.1.264`. Внутри будет папка `das-forge-core`.

```
cd C:\Users\<имя>\Downloads\das-forge-core-0.1.264\das-forge-core
```

## 2. Поставить зависимости

Папки `node_modules` в архиве нет, она ставится каждый раз заново (около 30 секунд).

```
npm install
```

npm напишет, что установочные скрипты трёх пакетов заблокированы. В новой папке это бывает каждый раз: разрешение из прошлой папки сюда не переносится.

```
npm install-scripts approve cpu-features ssh2 argon2
```

Команда называется `install-scripts` (во множественном числе, через дефис). Без этого шага не соберётся `argon2`, а с ним вход в систему.

## 3. Проверить lock-файл и поставить по нему

```
npm run lock:check
npm ci
```

`lock:check` отвечает «lock file is in step with the package.json files». Если он перечисляет расхождения, в архиве поменялись зависимости без обновления `package-lock.json`: дальше не идите и сообщите разработчику. `npm ci` ставит ровно то, что записано в lock-файле.

## 4. Статическая проверка и тесты

```
npm run lint
npm test
```

- **`npm run lint`** (ESLint). Ошибок (`error`) должно быть 0. Предупреждения (`warning`) сборку не ломают, но их число не должно расти от версии к версии.
- **`npm test`** запускает все тесты ядра и примера. В конце смотрите строки `Test Files` и `Tests`: должно быть `failed` отсутствует или 0. Пропущенные (`skipped`) допустимы.

Если что-то упало, сохраните вывод целиком (в CMD: `npm test > test.log 2>&1`) и передайте файл `test.log`.

## 5. Сценарии в браузере (e2e)

Это тесты, где настоящий браузер открывает приложение, входит под администратором, нажимает кнопки и проверяет, что страницы ведут себя как нужно. Ловят то, чего не видят обычные тесты: сломанный скрипт на странице, пропавшую кнопку, неверный редирект.

**Что нужно один раз** (браузер скачивается в общую папку пользователя, а не в проект, поэтому повторять для каждой версии не надо):

```
npx playwright install chromium
```

**Запуск** из корня `das-forge-core`:

```
npm run test:e2e
```

Playwright сам поднимает приложение на **пустой временной базе** (папка во временных файлах системы) с известным администратором `e2eadmin`, порт 4399. Ваша рабочая база и настоящие пользователи не затрагиваются. Если порт занят, задайте другой: `set E2E_PORT=4400` перед командой.

Что проверяется сейчас (файлы `examples/workshop/e2e/*.e2e.js`):

| Файл | Сценарий |
|---|---|
| `admin-users.e2e.js` | администратор создаёт, правит, сбрасывает пароль и удаляет учётную запись; у своей строки кнопок действий нет; гость не открывает раздел «Пользователи» |
| `admin-sections.e2e.js` | страницы входа и «Забыли пароль»; разделы «Задачи», «Почта», «Конфигурация»; вкладка «Входы» и экспорт JSON в аудите; режим обслуживания (посетителям 503, администратор его выключает) |
| `admin-paging.e2e.js` | длинный список разбит на страницы, кнопка «Развернуть» догружает остальное; реестр обработки открывается и скачивается как CSV |

Сценариев пока немного, список будет расти вместе с разделами админки. Правило для новых разделов: страница с интерактивным скриптом (живая лента, постраничная загрузка, диалоги) получает свой сценарий, потому что обычные тесты не запускают браузерный код.

**Если сценарий упал.** Playwright кладёт отчёт в `examples\workshop\test-results\`: снимок экрана и трассу (`trace.zip`). Посмотреть трассу пошагово:

```
npx playwright show-trace examples\workshop\test-results\<папка сценария>\trace.zip
```

Для передачи достаточно снимка экрана и текста ошибки из консоли.

**Тонкости:**
- Сценарии нажимают кнопки по **английским** названиям (`locale: 'en-US'` в `playwright.config.js`). Поменяли название кнопки в англоязычных текстах, поправьте и сценарий.
- Приложение отдаёт самоподписанный сертификат, поэтому браузер запускается с `ignoreHTTPSErrors`.
- На CI e2e идут только на Linux в одном браузере (Chromium).

## 6. Запуск для ручной проверки

```
npm start
```

Приложение (workshop) откроется на `https://127.0.0.1:9002` (HTTP на 9001 только перенаправляет). Команды управления вводятся в строке `>` внизу окна, см. «Командная строка». Базу и сертификаты приложение создаёт в `examples\workshop\data` внутри этой папки. Чтобы сохранить данные предыдущей версии, скопируйте её папку `examples\workshop\data` в новую до первого запуска. Если не копировать, всё создастся заново: пользователи и журнал будут пустыми.
