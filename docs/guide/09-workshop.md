# Workshop — эталонное приложение

## Назначение

`examples/workshop` — рабочий пример подключения ядра: минимальный, но настоящий код без псевдокода. Новое приложение платформы начинают с копирования его структуры. Любой фрагмент в этой документации со ссылкой на `examples/workshop/…` — реальный файл, покрытый тестами.

## Главная страница

Страница `/ui` — витрина возможностей ядра: живые показатели (активы, пользователи, сессии, версия ядра), группы возможностей с короткими пояснениями и ссылками (вход и учётная запись, живые обновления, данные и права, администрирование, приватность и инциденты, открытые страницы, эксплуатация) и список «Что попробовать». Ссылки показываются только на страницы, которые эти права позволяют открыть. Код: `renderHomeBody` в `examples/workshop/src/routes.js`, тексты — раздел `home` в `messages.js`; тест `home.test.js`.

## Структура

| Файл | Что показывает |
|---|---|
| `app.config.js` | настоящий файл конфигурации |
| `src/context.js` | единая точка сборки: конфигурация → база → брендинг → авторизация → планировщик; использует и сервер, и CLI |
| `src/server.js` | Express: порядок промежуточных обработчиков, сессии с `isUserActive`, `attachUser({ revalidate })`, админка (`createAdmin`), остановка |
| `src/routes.js` | подключение `accounts.mountAccountRoutes` (вход с TOTP и кодами восстановления, смена и сброс пароля, аутентификаторы живут в ядре), `/assets` (CRUD, права на поля, стоимость по разрешению, QR, логотип с проверкой содержимого), потоки событий SSE |
| `src/pages.js` | HTML на сервере без клиентского фреймворка: журнал аудита, система, Realtime Lab (страницы входа и «Аккаунт» рисует ядро) |
| `src/records.js` | SQL без ORM для таблицы `assets`, демо-данные |
| `src/roles.js` | список ролей — единый для CLI, админки и API |
| `src/messages.js` | каталог текстов (i18next, пространство `workshop`) для всех страниц, `scriptTexts` для браузерных скриптов (подробнее — «Переводы») |
| `src/alerts-commands.js` | команды `alerts test` и `alerts list`: проверка алертов вживую (подробнее — «Эксплуатация» → «Алерты») |
| `src/doctor-categories.js` | свои проверки для `doctor` и раздела «О системе» |
| `src/modules/reporting-module.js` | пример модуля приложения |
| `migrations/` | синхронные `up(db)`, применяются при старте |
| `bin/app.js` | CLI поверх того же контекста |
| `assets/brand/` | неизменяемый логотип поставщика (светлый и тёмный) |
| `test/`, `e2e/` | HTTP-тесты через `registerRoutes()`, smoke сервера, сценарий Playwright для пользователей |

## Что требует внимания при разработке приложения

| Тема | Правило |
|---|---|
| Порядок middleware | `requestId` → заголовки безопасности → сессии → маршруты → обработчики ошибок последними |
| Сессии | передавайте `isUserActive`, чтобы блокировка пользователя обрывала сессии; `attachUser` кэширует по сессии и проверяет снимок, смена пароля действует сразу |
| Права | проверяйте на сервере (`requirePermission`), а не только прячьте кнопки; поля — через `fieldPermissions` |
| Загрузки | только `validateUpload` / `acceptImageUpload`: содержимое, не имя файла |
| Роли | один список (`roles.js`) для CLI, админки и API |
| Остановка | `registerGracefulShutdown` с `closeAllSseStreams` в `onDrainStart` |
| Брендинг | оболочка берёт тему и логотип из `brandOf(req)`; настройки компании — в админке «Оформление» |
| Свой doctor | категории приложения добавляйте в `doctor-categories.js` |

## Шаблон приложения

`templates/app` — заготовка нового приложения платформы. Отличие от workshop: workshop показывает, **как** подключается каждый модуль (в том числе двухфакторная аутентификация, «Забыли пароль», загрузки, потоки событий), шаблон даёт **минимум, с которого начинают**, и его копируют. Он живёт отдельно от рабочих пространств: копия должна стоять на своих ногах, поэтому его зависимость `@das-forge/core` указывает диапазон выпущенной версии, а не путь внутри репозитория.

```bash
cp -r templates/app ../my-new-app && cd ../my-new-app
# имя (my-app, My App), порт (следующий 9N02), диапазон ядра в package.json
npm install && npm run cli -- config check && npm start && npm test
```

| Есть в шаблоне | Нет в шаблоне (берите из workshop) |
|---|---|
| единая сборка `context.js`, порядок обработчиков в `server.js` | двухфакторная аутентификация, коды восстановления |
| вход с блокировками и ровным временем ответа, выход, `/me`, смена временного пароля | «Забыли пароль» по почте, страница «Аккаунт» |
| роли и права на сервере, пример API `/notes` с проверкой прав и страница `/ui/notes` | загрузки файлов, потоки событий (SSE), собственный CRUD пользователей |
| админ-панель ядра, политики, оформление, копии, журналы, алерты | демонстрационный модуль отчётов |
| переводы ru/en на i18next, `scriptTexts` для скриптов | |
| CLI с готовыми группами команд ядра, миграции, `doctor` | |
| `Dockerfile` и `docker-compose.yml` для отдельного приложения | |
| тест по настоящему HTTP-стеку и тест текстов | |

Порядок работы подробно описан в `templates/app/README.md` (как переименовать, как убрать пример «заметки», как обновлять ядро). Чтобы шаблон не отстал от ядра, `npm run test:template` (`scripts/test-template.mjs`) копирует его во временную папку, подставляет `file:`-путь к `packages/core`, ставит зависимости и гоняет его тесты; этот шаг есть в CI. Образец для проверки по HTTP — `templates/app/test/app.test.js`.

## Запуск и тесты

См. «Быстрый старт». Тесты workshop — `npm test --workspace=workshop`; им нужны реальные express, pino, sharp, jsdom, otplib (устанавливаются `npm install`).

## Что мастерская показывает из последнего

- **Раздел работы приложения** `/control` отдельно от `/admin`: копии, режим обслуживания, объявление, задачи, рассылка (`createAdmin({ controlPath })`).
- **Колокольчик и значок роли** в шапке; страница `/ui/notifications` с личным выбором «Безопасность» / «Работа системы». Новые алерты уходят администраторам (`createAlerts({ onRaised })` → `notifyRole('admin', …)`).
- **Лимиты на обзоре** админки (демонстрационные: база 1 ГБ, аудит 5 млн записей, сессии 10 000).
- Самостоятельная регистрация в мастерской **не включена**: включается `auth.registration.enabled` и требует настроенной почты.
