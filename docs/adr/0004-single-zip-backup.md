# 0004. Резервная копия: один zip, потоковая запись

Статус: принято
Дата: 2026-10-16

## Контекст
Нужна копия, которую можно проверить, перенести и восстановить: база данных и загруженные файлы вместе.

## Решение
Одна копия = один zip с базой и файлами. Запись и чтение потоковые: `yazl` (запись) и `yauzl` (чтение), а не `adm-zip` (он грузит всё в память; остаётся только в приложениях пользователя). Копия проверяется хешем, поддерживается шифрование (`.zip.enc`), копирование на смонтированный путь и по SFTP. Устаревшего формата не поддерживаем, пока проект не в продакшене.

## Альтернативы
Отдельные файлы базы и загрузок: сложнее проверить целостность и согласованность. `adm-zip` везде: проще, но память растёт с размером копии.

## Последствия
Восстановление идёт по полному конвейеру проверок (хеш, структура архива, блокировка сервера). Загрузки при восстановлении откладываются в сторону, а не затираются.

## Безопасность и эксплуатация
Ключ шифрования хранится отдельно от копии. Без ключа копии не открываются, и проверка это подтверждает тестом.

## Выкатка и откат
Копии создаёт плановая задача; восстановление только из командной строки (`backup restore`), не из интерфейса.
