# 0009. Два срока хранения аудита: запись и персональные подробности

Статус: принято
Дата: 2026-11-10

## Контекст
Данные журнала аудита нужны для функциональности, безопасности и расследования (решение владельца). Разным данным нужен разный срок: сам факт события («кто-что-когда-результат») нужен долго, а настоящий логин и IP — персональные данные — не дольше, чем требуют цели.
Требования регуляторов: 152-ФЗ ст. 5 ч. 7 и GDPR ст. 5(1)(e) требуют хранить идентифицируемые данные не дольше необходимого; конкретных сроков в проверенных приказах ФСТЭК №21 и №239 нет, срок определяет организация; рекомендация CNIL — 6–12 месяцев, до 3 лет при обосновании; PCI DSS 10.5.1 — не менее 12 месяцев. Проверка источников и пометки — в истории обсуждения; не проверены нормативы Банка России, приказ №17, NIS2, DORA.
Ограничение: журнал — цепочка хешей, удаление строки из середины выглядит как подделка (`verifyChain`).

## Решение
Не делить цепочку и не удалять строки по категориям. Использовать уже существующее устройство (ADR 0002): хеш считается от псевдонимов, а настоящие логин и IP лежат отдельно в `audit_subjects`. Новая настройка `audit.personalDataDays` (0 = выключено) и ежедневная задача `audit-personal-gc` удаляют соответствия, которые не встречались N дней. Строка остаётся, поля читаются как «[erased]», цепочка валидна. Срок самих строк — прежний `audit.retentionDays`. Операция пишется в журнал (`audit.personal_data.purge`).

## Альтернативы
Одна цепочка и общий срок по самой долгой категории: IP живёт столько же, сколько вход. Две цепочки (отдельная таблица безопасности): новая схема БД и миграция, пока не нужна. Удаление по категориям с записью-«швом»: подделку нельзя отличить от удаления.

## Последствия
Соответствие считается по последнему появлению значения, а не по возрасту строки: активный пользователь или постоянный адрес сохраняют соответствие, пока их видят; стирается всё, что не встречалось N дней. Старые строки до псевдонимов (до 0.1.82) хранят значения открыто и уходят вместе со строками по `retentionDays`. Свободный текст в `meta` (например, значения в «что изменилось») не псевдонимизируется и живёт со строкой. Если понадобится стирать по возрасту строки даже для активных, нужны псевдонимы с периодом (смена схемы `audit_subjects`) — отдельное решение.

## Безопасность и эксплуатация
Значение по умолчанию 0 — поведение не меняется. Рекомендуемый порядок: определить сроки в политике организации (мера РСБ.1 приказа №21 и аналоги), записать их в настройки. Работа ведётся ежедневно в 03:55, запись об очистке попадает в журнал и в его внешнюю копию.

## Выкатка и откат
Включение: `audit.personalDataDays` в конфигурации приложения. Откат: поставить 0; уже стёртые значения не восстанавливаются (по смыслу решения).
