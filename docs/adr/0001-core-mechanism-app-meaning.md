# 0001. Ядро даёт механизм, приложение даёт смысл

Статус: принято
Дата: 2026-10 (с первых версий)

## Контекст
Ядро объединяет четыре приложения (procure-it, atlas-ao, net-monitor, it-assets). Если ядро начнёт знать их предметную область, оно перестанет быть общим.

## Решение
Ядро реализует механизмы (пользователи, аудит, резервные копии, права на поля, навигация), а что они значат для предметной области, задаёт приложение через контракты: `ApplicationConfig`, `Module`, `DatabaseAdapter`. Пример: права на поля актива не вшиты в ядро, их объявляет зарегистрированный модуль. Данные проверяются схемой (Zod), поведенческие интерфейсы проверяются утиной типизацией (`assertDatabaseAdapter`).

## Альтернативы
Ядро с жёстко заданными сущностями: проще на старте, но каждое приложение тащит чужие поля. Общая схема данных на всех: связывает релизы приложений.

## Последствия
Новое приложение пишется через контракты и не правит ядро. Цена: контракты нужно проверять на примере, для этого есть `examples/workshop`. Принцип «не строить фасад»: если у поля нет работающего потребителя, оно не изображает работу (например, тип аутентификатора `webauthn` закрыт, пока нет проверки).

## Безопасность и эксплуатация
Права проверяются на стороне ядра по объявленным модулем правилам.

## Выкатка и откат
Действует с начала проекта; откат не предусмотрен.
