# Записи об архитектурных решениях (ADR)

Здесь коротко записано, **почему** сделано так, а не иначе. Код показывает «как», история изменений показывает «когда», а причины со временем забываются и их приходится выяснять заново.

Первые восемь записей восстановлены задним числом по журналу разработки; в них нет ничего, что не было решено на самом деле, но формулировки «альтернатив» написаны сейчас. Новые записи пишутся в момент решения.

## Когда писать
Выбор, который трудно отменить или который будет удивлять читателя кода: формат данных, граница между ядром и приложением, зависимость, схема безопасности, способ резервного копирования. Мелкие правки в ADR не нужны.

## Как
Скопировать `0000-template.md` в `NNNN-короткое-имя.md`, заполнить, добавить строку в таблицу. Принятую запись не переписывают: если решение изменилось, пишут новую и ставят в старой статус «заменена записью NNNN».
