# Аудит зрелости ядра перед первым релизом

Версия ядра на момент аудита: **0.1.163**; таблица «Что есть» приведена в соответствие с версией **0.1.180** (пункты списка «Что закрыть до 0.2.0» закрыты, кроме онлайн-проверки паролей). Дата: 31.10.2026. Аудит по коду и документации; сервер для этого не запускался, сеть из среды разработки недоступна.

## Вывод

Ядро готово к первому релизу (0.2.0) как **основа для внутренних приложений за обратным прокси**. Для приложений, открытых в интернет без прокси и без дополнительных мер, не хватает нескольких недорогих вещей (раздел «Что закрыть до 0.2.0»). Крупные пробелы (пароль-ключи, строгий CSP без `unsafe-inline` для стилей) на безопасность первого релиза не влияют и записаны как работа после него.

Серьёзных дыр класса «обойти вход», «чужая сессия», «выполнить код» при чтении кода не найдено. Это не доказательство их отсутствия: независимый разбор и проверку на живом сервере ничто не заменяет.

## Границы аудита

- Состояние зависимостей (уязвимости) из среды разработки проверить нельзя: реестр npm недоступен. Эту часть закрывает ядро само: категория «Dependencies» диагностики и задача `audit` в CI; **перед релизом выполните `npm audit --omit=dev` и `npm audit signatures` у себя** и приложите результат к решению о выпуске.
- Записи о версиях Node (Current и LTS) берутся с `nodejs.org` диагностикой; расписание проекта Node: чётный выпуск становится LTS в октябре года выхода, то есть 26-я ветка переходит в LTS в октябре 2026. Статус на сегодня сверьте на `nodejs.org` до релиза.
- «Есть» значит: код и тест существуют. «Частично» — работает, но с оговоркой. «Нет» — не реализовано.

## Что есть (по областям)

| Область | Состояние |
|---|---|
| Пароли | argon2id; сброс по одноразовой ссылке, ответ одинаков для существующей и несуществующей почты; смена при первом входе |
| Парольная политика | раздел админки: профили «NIST» и «ФСТЭК», длина (12 по умолчанию, отдельная для администраторов), классы символов, срок действия (по умолчанию без ограничения), запрет повторов, запрет логина, части e-mail и названия приложения, список типовых и локальный файл утёкших паролей; массовое «потребовать смену» |
| Вход | перебор ограничен (трекер неудач, баны по адресу и учётной записи, лимит запросов); блокировка не раскрывает, существует ли учётная запись; время ответа выровнено фиктивным хешем |
| Второй фактор | TOTP, коды восстановления, ключи TOTP шифруются и ротируются; шаг «подтвердите заново» для опасных действий |
| Сессии | подписанная cookie `HttpOnly`, `SameSite=Lax`, `Secure` по протоколу; ключ подписи выводится из секрета; пересоздание сессии при входе; абсолютный и по простою срок; серверное хранилище, отзыв и принудительный выход |
| CSRF | по заголовкам `Origin`, `Sec-Fetch-Site`, `Referer`; строгие пути (вход); внешние источники только по списку |
| Заголовки | CSP в режиме отчёта (`security.csp.reportOnly`) и приёмник нарушений в аудит; `Clear-Site-Data` при выходе (`auth.clearSiteDataOnLogout`); CSP с nonce для скриптов, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri`, `form-action`; COOP/CORP; `nosniff`; Referrer-Policy; Permissions-Policy; HSTS только по HTTPS (с проверкой условий preload) |
| Вход и вывод | строгие схемы Zod, экранирование, `innerHTML` один раз и для собственного SVG; загрузки перекодируются, SVG очищается, архивы проверяются, имена не берутся от клиента |
| Cookie сессии | опционально `__Host-das_session` (`auth.hostCookiePrefix`) |
| Сообщения об уязвимостях | `/.well-known/security.txt` (`security.securityTxt`) |
| Кража пароля | письмо о входе с нового устройства (`auth.newDeviceNotice`) |
| Подмена адресов | `Host` принимается только из списка (`allowedHosts`), редирект с HTTP не открытый; `X-Forwarded-*` только от доверенных прокси; диагностика предупреждает о `trustProxy: true` и о рассогласовании с `https.mode` |
| Данные | база SQLite в режиме WAL, снимок `VACUUM INTO` с параметром, копии шифруются AES-256-GCM, проверка копий в админке, восстановление только из CLI; цепочка хешей аудита с якорем в журнал |
| Приватность | псевдонимы в аудите, удаление персональных данных, повторное применение удалений после восстановления; реестр обработки (`privacy registry`); реестр инцидентов со сроками уведомления (раздел «Инциденты», `privacy incident`) |
| Письма | очередь, DKIM, проверка DNS-записей SPF и DMARC в диагностике |
| Наблюдаемость | метрики Prometheus (`/metrics`, закрыты по умолчанию); массовая рассылка пользователям (раздел «Рассылка»); списки админки постраничные с кнопкой «развернуть»; отдельный порт админки (`server.admin`) |
| Эксплуатация | диагностика (в том числе категории «Dependencies» и «Hardening»), алерты, режим обслуживания, плавное завершение, права файлов и запуск не от root проверяются |
| Цепочка поставок | lock-файл проверяется (`lock:check`, `lockfile-lint`), `npm audit` и подписи в CI, CodeQL, gitleaks, Trivy, SBOM при релизе, SECURITY.md, Dependabot; публикация с provenance |

## Что закрыть до 0.2.0

Пункты 1–3 (`__Host-`, `security.txt`, письмо о новом устройстве), 5 (CSP в режиме отчёта) и 6 (`Clear-Site-Data`) сделаны и перенесены в «Что есть». Пункт 4 закрыт частично: проверка по локальному файлу есть, онлайн-вариант нет.

4. **Проверка пароля по базе утёкших через сеть** (k-анонимность, отправляется только 5 символов хеша): опциональная, выключена по умолчанию; при недоступной сети не блокирует. Требует решения владельца: это исходящий запрос к внешнему сервису. Локальный файл (`auth.passwordBlocklistFile`) уже работает и ничего не отправляет.

## Защита пользователя от подделки

| Угроза | Защита | Остаток риска |
|---|---|---|
| Поддельный запрос от чужого сайта (CSRF) | заголовки браузера, `SameSite=Lax` | запросы без браузерных заголовков допускаются только без cookie сессии |
| Подмена `Host` и `X-Forwarded-*` | список `allowedHosts`, доверие только перечисленным прокси | неверная настройка прокси на стороне оператора; диагностика предупреждает |
| Открытый редирект | редирект HTTP→HTTPS только на известные хосты | — |
| Кликджекинг | `frame-ancestors 'none'`, `X-Frame-Options: deny` | — |
| Фишинговая ссылка в письме | адрес в письмах берётся из `email.baseUrl`, а не из запроса | неверный `baseUrl` |
| Подделка отправителя | DKIM-подпись, диагностика SPF/DMARC | записи DNS создаёт оператор |
| Подмена загружаемого файла | тип определяется по содержимому, перекодирование, очистка SVG | — |
| Подмена записей аудита | цепочка хешей, якорь в журнал, проверка по расписанию | запись в журнал за пределами приложения |
| Подмена зависимостей | lock-файл, `lockfile-lint`, подписи, SBOM | компрометация самого реестра до выхода советов |
| Перехват при самоподписанном сертификате | диагностика предупреждает; режим `reverse-proxy` для настоящего сертификата | внутренние сети без доверенного центра сертификации |

## Сверка с планом

- Этап F (портирование IT Assets) приостановлен решением владельца; на готовность ядра не влияет.
- Первый релиз (0.2.0) по-прежнему выпускает владелец, когда будут готовы учётная запись npm, организация и токен (или Trusted Publisher) и закрыты шаги вне репозитория из [раздела о безопасности репозитория](guide/10-operations.md).
- Третий язык интерфейса отложен.
- Из дорожной карты остаётся командная утилита обновления ядра и совместимости версий; разумна после первой публикации.
- Список зависимостей соответствует `docs/dependencies-target.md`; собственный код вместо готового пакета появился только там, где пакета нет (расшифровка cron, планировщик на таймерах) и это записано в соответствующих разделах.

## Как использовать этот документ

Пункт «Что закрыть до 0.2.0» — предложение очереди работ, а не обязательство: каждый берётся в работу отдельной поставкой по решению владельца. После каждого закрытого пункта строка переносится в раздел «Что есть».
