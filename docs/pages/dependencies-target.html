Целевые зависимости (рабочий ориентир)

Список от владельца проекта: пакеты, которые уже используются в четырёх приложениях (procure-it, atlas-ao, net-monitor, it-assets) и которые планируется выносить в ядро по мере подхода к соответствующей зоне ответственности. Версии на момент составления списка; перед подключением каждого пакета сверяем актуальную версию на npm.

Рабочие ориентиры при разработке ядра: этот файл и docs/audit-findings.md. docs/roadmap.md заморожен (исторический ориентир), docs/index.html ведомый — синхронизируется с кодовой базой.

Полный и всегда актуальный список зависимостей ядра, шаблона и разработки собирается из package.json и лежит в руководстве «Зависимости». Этот файл хранит решения и историю подключений.

Решения по ходу работы

  • otplib ^13.6.0 — в ядре с 0.1.42 (TOTP).
  • @prometheus-io/client 0.16.0 (точная версия) — в ядре с 0.1.178 (метрики Prometheus; преемник prom-client, версия пока до 1.0, поэтому закреплена точно; ядро оборачивает его тонким слоем observability).
  • yauzl ^3.4.0 + yazl ^3.3.1 — в ядре с 0.1.45, только для бэкапов (один backup-<ts>.zip: база + uploads + manifest, потоковая запись и чтение, CRC проверяется своим кодом). adm-zip в ядро не берём: он собирает архив в памяти; в приложениях он остаётся для их собственных задач. Проверка загружаемых архивов (аудит B12, 0.1.46): собственный читатель каталога (быстрая проверка заявленных размеров) + yauzl для реальной распаковки потоком (реальный бюджет размера, CRC, имена).
  • Старого формата бэкапов нет и не поддерживается: проект ещё не в проде.
  • pino ^10.4.0 + pino-http ^11.0.0 — в ядре с 0.1.47 (core/logs: createLogger поверх pino, accessLog поверх pino-http; своя редакция секретов по имени ключа остаётся сверху, т.к. у pino редакция только по точным путям). pino-pretty (dev) в ядро не входит: подключается в приложении для читаемого вывода в разработке.
  • express-rate-limit ^8.7.1 — в ядре с 0.1.48 (createRateLimiter — тонкая обёртка: JSON-ответ 429, Retry-After, ключ по IP с группировкой IPv6; заголовки RateLimit draft-7). createFailureTracker (экспоненциальная блокировка после неверных паролей/TOTP) остаётся своим кодом: у пакета такой функции нет. Опции now и maxKeys у createRateLimiter убраны (у MemoryStore пакета их нет).
  • cors ^2.8.6 — в ядре с 0.1.50 (createCors: точный список origin из security.cors.origins, пустой = выключен, без масок, null не разрешается).
  • compression ^1.8.2 — в ядре с 0.1.58 (createCompression: SSE не сжимается, opt-out X-No-Compression).
  • i18next ^27.0.1 — в ядре с 0.1.108 (i18n.createI18n): переводы ru/en, пространства имён (ядро + каждое приложение), экранирование подстановок, русские множественные формы, проверка полноты (missingKeys). Выбран как стандарт де-факто вместо самописных словарей и вместо пакета i18n (mashpie, только Express/JSON). Подключается лениво.
  • express-session ^1.19.0 — в ядре с 0.1.65 (optional peer): подписанная cookie + собственное хранилище в SQLite (auth.createSessionStore), отзыв по user_id, idle-timeout, хеш id в БД. Первоначально было решено не брать (сессии свои); пересмотрено по требованию использовать проработанные пакеты. cookie-parser остаётся peer-зависимостью (нужен CSRF).
  • nodemailer ^10.4.0 — в ядре с 0.1.59 (core/email: именованные системные письма ru/en, лимиты, DKIM, ленивая загрузка). Реальная отправка пока не проверена.
  • uuid ^14.0.3 — в ядре с 0.1.67 (v4() вместо crypto.randomUUID(): request id, имена загружаемых файлов, logger). Прежнее решение «не брать» пересмотрено по требованию использовать общий пул.
  • multer ^2.5.0 — в ядре с 0.1.67 (files.createMultipartUpload: один файл в память под жёстким лимитом, JSON-ошибки; загружается лениво). Загрузка логотипа в workshop — multipart/form-data.
  • pino-pretty ^13.1.3 — optional peer + dev с 0.1.67 (createLogger({pretty: true}); без пакета откат на JSON с предупреждением).
  • supertest ^7.3.0 (dev, workshop) и jsqr ^1.4.0 (dev, core) — с 0.1.67: реальный HTTP в тесте загрузки логотипа; тест QR декодирует настоящий SVG обратно.
  • libheif-js ^1.23.5 — в ядре с 0.1.69 (HEIC/HEIF-загрузки: WASM-декодер → обязательный re-encode через sharp, по умолчанию в JPEG; у готовых сборок sharp нет HEVC-декодера).
  • docx ^9.15.3 — в ядре с 0.1.69 (files.buildDocx: отчёт .docx из данных; ленивая загрузка).
  • @playwright/test ^1.63.0 — dev, workshop, с 0.1.70 (npm run test:e2e --workspace=workshop: браузерный сценарий по учётным записям на одноразовой базе). playwright отдельно не подключён (достаточно @playwright/test).
  • adm-zip в ядре не используется (yauzl/yazl, см. выше).
  • yauzl ^3.4.0 — с 0.1.74 единственный читатель ZIP, в том числе для проверки загрузок (files.inspectZip, listZipEntries); собственный читатель оглавления (zip-reader.js) удалён по решению владельца.
  • Excel (xlsx): отдельной библиотеки нет, по решению владельца из-за открытых уязвимостей SheetJS и размера exceljs: писатель .xlsx и читатели .xlsx, .xlsb, .ods, .xls написаны в ядре (zip — на yauzl/yazl, остальное свой разбор без зависимостей; читатели строгие: лимиты, без макросов, внешних ссылок, DOCTYPE и вычисления формул; чтение чужих файлов можно изолировать в отдельный поток).
  • Сессии: с 0.1.73 только express-session + auth.createSessionStore; самописный сессионный код удалён.
  • node:crypto (без пакета) — с 0.1.71 шифрование бэкапов (AES-256-GCM, scrypt) и с 0.1.79 ключи TOTP списком: стандартные примитивы, свой только формат контейнера.
  • ssh2 ^1.17.0 — в ядре с 0.1.83 (SFTP-приёмник бэкапов; владелец одобрил install-scripts ssh2 и cpu-features).
  • Решено владельцем (ранее): ssh2 — для SFTP-приёмника бэкапов (0.1.82; версию сверить на npm перед подключением; альтернатива «копия на смонтированный путь» без пакета реализуется первой). Приёмники логов (stdout, file, syslog по node:net/node:tls/node:dgram, HTTP через встроенный fetch, pino.multistream) — без новых пакетов.

Разбор приложений (этап H, 0.1.90)

  • bcrypt/bcryptjs не нужен: it-assets уже удалил bcrypt (только argon2id); в 0.1.88 была добавлена, в 0.1.90 удалена bcryptScheme вместе с bcryptjs.
  • ldapts ^9.2.0 (актуально на 0.1.100) — используют it-assets (^9.2.0) и net-monitor (^9.0.0); подключён в core/ldap с 0.1.95 (подгружается по требованию; запись в lock-файле перенесена из lock it-assets: 9.2.0 + strict-event-emitter-types 2.0.0).
  • pino-roll ^4.0.0 (it-assets, net-monitor) — ротация логов; в ядре остаётся собственная ротация файлового приёмника, пакет не берём.
  • @node-rs/argon2 (it-assets) vs argon2 (остальные): формат строки одинаковый; ядро использует argon2.
  • Только в приложениях, в ядро не переносятся: net-snmp, node-routeros, pdf-lib, pngjs, adm-zip (ядро — yauzl/yazl).
