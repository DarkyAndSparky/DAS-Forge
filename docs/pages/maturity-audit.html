Аудит зрелости ядра перед первым релизом

Версия ядра на момент аудита: 0.1.163; таблица «Что есть» приведена в соответствие с версией 0.1.180 (пункты списка «Что закрыть до 0.2.0» закрыты, кроме онлайн-проверки паролей). Дата: 31.10.2026. Аудит по коду и документации; сервер для этого не запускался, сеть из среды разработки недоступна.

Вывод

Ядро готово к первому релизу (0.2.0) как основа для внутренних приложений за обратным прокси. Для приложений, открытых в интернет без прокси и без дополнительных мер, не хватает нескольких недорогих вещей (раздел «Что закрыть до 0.2.0»). Крупные пробелы (пароль-ключи, строгий CSP без unsafe-inline для стилей) на безопасность первого релиза не влияют и записаны как работа после него.

Серьёзных дыр класса «обойти вход», «чужая сессия», «выполнить код» при чтении кода не найдено. Это не доказательство их отсутствия: независимый разбор и проверку на живом сервере ничто не заменяет.

Границы аудита

  • Состояние зависимостей (уязвимости) из среды разработки проверить нельзя: реестр npm недоступен. Эту часть закрывает ядро само: категория «Dependencies» диагностики и задача audit в CI; перед релизом выполните npm audit --omit=dev и npm audit signatures у себя и приложите результат к решению о выпуске.
  • Записи о версиях Node (Current и LTS) берутся с nodejs.org диагностикой; расписание проекта Node: чётный выпуск становится LTS в октябре года выхода, то есть 26-я ветка переходит в LTS в октябре 2026. Статус на сегодня сверьте на nodejs.org до релиза.
  • «Есть» значит: код и тест существуют. «Частично» — работает, но с оговоркой. «Нет» — не реализовано.

Что закрыть до 0.2.0

Пункты 1–3 (__Host-, security.txt, письмо о новом устройстве), 5 (CSP в режиме отчёта) и 6 (Clear-Site-Data) сделаны и перенесены в «Что есть». Пункт 4 закрыт частично: проверка по локальному файлу есть, онлайн-вариант нет.

  1. Проверка пароля по базе утёкших через сеть (k-анонимность, отправляется только 5 символов хеша): опциональная, выключена по умолчанию; при недоступной сети не блокирует. Требует решения владельца: это исходящий запрос к внешнему сервису. Локальный файл (auth.passwordBlocklistFile) уже работает и ничего не отправляет.

Сверка с планом

  • Этап F (портирование IT Assets) приостановлен решением владельца; на готовность ядра не влияет.
  • Первый релиз (0.2.0) по-прежнему выпускает владелец, когда будут готовы учётная запись npm, организация и токен (или Trusted Publisher) и закрыты шаги вне репозитория из раздела о безопасности репозитория.
  • Третий язык интерфейса отложен.
  • Из дорожной карты остаётся командная утилита обновления ядра и совместимости версий; разумна после первой публикации.
  • Список зависимостей соответствует docs/dependencies-target.md; собственный код вместо готового пакета появился только там, где пакета нет (расшифровка cron, планировщик на таймерах) и это записано в соответствующих разделах.

Как использовать этот документ

Пункт «Что закрыть до 0.2.0» — предложение очереди работ, а не обязательство: каждый берётся в работу отдельной поставкой по решению владельца. После каждого закрытого пункта строка переносится в раздел «Что есть».
